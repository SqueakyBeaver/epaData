Project Introduction

The specific goal of this project is to design and implement a web application that can collect, store, manage, and visualize environmental and power-sector data obtained from the U.S. Environmental Protection Agency. This Flask-based web application will support:

  • Retrieving selected Environmental data records from the EPA website through the CAMD API.
  • Uploading environmental data from CSV or Excel Files, first performing proper quality control methods by validating the uploaded data.
  • A database in SQLite to store all retrieved data from the CAMPD API as well as locally verified and uploaded data. The database enforces relationships, uniqueness, and data integrity rules when appropriate.
  • Proper data search, download, and display according to the user’s requests.

Where to start

EPA Retrieval Pull emissions data from the EPA and save it as a dataset. Dataset Explorer Browse, search and rank the data you have saved. Upload Check a CSV or Excel file and add it to the database.

Data Sources

All data sources originate from environmental and power-sector data obtained from the U.S Environmental Protection Agency. Specifically sourced from the Clean Air Markets Program Data API.

Current Data Coverage

According to the Clean Air Market's Program Data website, "The Clean Air Markets Division began collecting its Power Sector Emissions Data in 1995 at the beginning of the Acid Rain Program. Affected EGUs report the following data to EPA:

  • Hourly emissions of sulfur dioxide (SO₂), nitrogen oxides (NOₓ), carbon dioxide (CO₂), and mercury (Hg) in short tons(1)
  • Facility information, such as unit type (e.g., tangential-fired boiler, combustion turbine, combined cycle), source category (e.g., electric utility, industrial boiler), owner, and location (including latitude and longitude)
  • Primary and secondary fuel type and the begin and end dates of use(2)
  • Emissions control device(s) used and the begin and end dates of those devices(3)
  • Hourly heat input expressed in million British thermal units, or mmBtu
  • Hourly gross electricity generation expressed in megawatt-hours, or MWh, or total steam generation of the unit expressed in thousand pounds of steam per hour
  • Type of emissions monitoring method and the begin and end dates of use
  • QA test information to validate hourly emissions data, such as testing date, test type, and test results (e.g., difference in readings between the emission monitor and the reference test)"
Emissions from power plants (electric generating units, or EGUs) are reported to EPA starting in different years1. The data does not say which fuel an EGU burned in a given hour2, and it does not include the hourly operating parameters or efficiency of control equipment3.

1 The largest coal-fired EGUs began reporting their SO₂, NOₓ, and CO₂ emissions to EPA in 1995, with the remaining fossil fuel-fired EGUs reporting these emissions beginning in 2000. EGUs began reporting mercury emissions to EPA in 2015, with some EGUs receiving extensions to 2017. ↩

2 Information about fuel burned in each hour is not reported to EPA. For example, if an EGU can burn both coal and natural gas, it does not specify which fuel is used each hour. ↩

3 Control equipment hourly operating parameters or efficiency is not reported to EPA. ↩

This project stores, displays, and will eventually allow users to analyze this data, which is freely available on the CAMPD website.
